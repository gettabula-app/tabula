# Changelog

All notable changes to Tabula are documented here, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Layers panel (TAB-198): **Layers** in the tool rail, the board menu or `Alt+L` lists everything on the board, the top first, with the items of a frame (or a kanban board) under it. Click to select on the board, drag (or `Alt+Up`/`Alt+Down`) to change the stacking order with one key write and one undo step, double-click or `F2` to rename, and the eye and lock to hide or lock (`H`, `L`). A tree with full keyboard support, Swiss, in every theme and on phones (a drag handle there). Viewers see it read-only. New object fields: `name` (the panel's name; a frame's title, as before) and `hidden`, which hides an item for everyone: it is not drawn, hit, selected, snapped to, connected to, or in PNG, SVG, the minimap or the session summary, and connectors to it and the contents of a hidden frame go with it. Hidden is not private: JSON and `.drift` keep it, MCP's `get_board` marks it `hidden: true`, the AI tools do not read it, templates drop it. The panel's title counts the hidden items. Kanban boards list their lanes and cards under them in layout order (moved on the board, not in the list), and a hidden lane or card leaves the board's layout, so the lane closes up. Groups will be nodes in the same tree (`docs/groups.md`). `npm run visual` has `layers` and `layers-hidden` states. Note for Johan: `name` now names any object in the layers list (a frame's title, as before); and `docs/presentations.md` proposes `Alt+L` for the laser pointer outside Play, which this panel already uses, so one of them needs another key.

### Changed
- Swiss pass on the board chrome and dialogs (TAB-48): trays, the quick-action bar, the properties panel, menus, popovers, the toast, the comment and history panels and the AI bar have square corners and a 1px hairline instead of a soft shadow, in every theme; buttons, inputs, segmented controls, chips, tiles and badges are square. Avatars, colour swatches and vote dots stay round. `--radius` is 0 and `--shadow` is the hairline.

- Images are now in the backups (TAB-127, slice 3: the backup walk). Until now the backup engine copied only the database, the rooms and the history, so the pictures people add to boards (files under `DATA_DIR/assets/`) were not in an off-site backup while the boards that show them were. The walk now includes every `assets/<aa>/<sha256>` file (one that does not hash to its own name is damaged and is left out and counted as skipped), and after the first run an image costs no more uploads. A whole-workspace restore accepts and verifies those files (each hashed against its name while staged) and moves `assets/` with the rest, so the restored workspace has the images of the backup and the later ones are kept aside with the old data; a board copy brings the board's pictures (from the backup unless the live store already has them) and gives the copy a row for each, so it shows what the original showed. See `docs/backups.md` and `docs/images.md`.
- Unused images are cleaned up (TAB-127, slice 3: the garbage collector). The relay now removes an image row, and its file once no board has a row for it, when nothing refers to it any more: not the board's live room (an open room counts) and not any version still kept in the board's history. A row is never removed in its first 7 days (a picture whose object has not synced yet survives), a board whose room or versions cannot be read is left alone, and a file with no row is removed only when it is also older than 7 days. It runs a couple of minutes after the relay starts and then once a day, logs one line, and writes an `assets.gc` audit row ("System removed 3 unused images") only when it removed something. Deleting an image from a board still deletes no bytes at once: undo, restore and history need them. See `docs/images.md`.
- Pictures are visible to the AI tools and the Markdown summary as metadata (TAB-127, slice 3). `get_board` and `get_objects` return an `image` object with its position and size, its type (`mime`), its natural size and its alt text (cleaned, cut at 300 characters and fenced like all board text); they never return its hash, a link or its bytes, and what the picture shows is not read. `update_objects` can move, resize, lock and delete a picture but cannot change which one it shows, and `create_objects` still does not make pictures. The Markdown summary lists a picture inside a frame as `Image: <alt text>`, or `Image (image/png, 640 x 480)` when it has no description, and votes on it count like votes on a note. See `docs/mcp.md`.
- Board files (`.drift`) now carry the pictures (TAB-127, slice 3). **Board file (.drift)** in the board menu stores every image of the board beside it (`assets/<sha256>` and a small `assets.json`, kept as they are, not compressed again), the desktop app's backup copy of each board includes them, and opening the file as a new board, into the current board (**Import a board file into this board**) or as a restored backup brings the pictures back: they are kept on this device at once and sent to the board's image store in the background, like any added picture. A picture that does not hold up (not an image of a supported type, over the size caps, more than 500 in a file) is left out and shows as a placeholder; the rest of the file opens as before. The JSON snapshot still holds references only, and now says so in a `note` when the board has pictures. The PNG, SVG and Markdown exports are unchanged. See `docs/images.md`.
- Bring forward and Send backward (TAB-108). `Ctrl+]` (`Cmd+]` on Mac) moves the selection one step forward: above the nearest object it overlaps, not to the very top, and `Ctrl+[` moves it one step back below the nearest overlapping object. Several objects move together and keep their order, an object that overlaps nothing above (or below) it stays where it is, and frames step among frames, since a frame always paints below everything else. Each is one undo step and writes only the objects that moved. The properties panel has both buttons between **Bring to front** and **Send to back**, and a right-click on an object (or on a selection) opens a new menu with the four stacking steps, **Duplicate**, **Lock** or **Unlock** and **Delete**; the keyboard shortcuts list names the new keys.
- Images on a board, the app (TAB-127, slice 1). Paste a picture (`Ctrl+V`), drop files on the board or choose **Image** (after Frame) in the left toolbar: PNG, JPEG, GIF, WebP and SVG, up to 10 at a time, laid out in a row at the pointer or the middle of the view and selected, as one undo step. A file is recognised by its bytes, scaled down to 2560 px on the longest side and re-encoded in the browser (which drops Exif and GPS and applies the rotation; a re-encode that comes out larger keeps the original), an SVG becomes a PNG, a GIF passes through untouched when it is within 10 MB and 2560 px, and anything else is refused with a message while the other files still go in. The picture is stored on this device at once and sent to the relay in the background; while it is on its way, or offline, it shows from the local copy for you and as "Image not uploaded yet" for others, and goes up when the connection is back (oldest first, three at a time, with a growing delay), after which every client shows the same file. An image has the usual box behaviour (move, resize with the proportions kept, rotate, lock, frames, comments, connectors) plus **100%** and **Alt text** in the quick-action bar. A picture that cannot be shown (no access, not found, offline) draws a placeholder that says why. PNG and SVG export include the pictures; saving a template leaves images out and says how many. Images are cached in IndexedDB (200 MB, cleared on sign-out). The Image button is hidden when the server reports no image support.

- Images on a board, the server (TAB-127, slice 2; the **Image** button, paste and drop follow). `POST /api/boards/:id/assets` takes the raw bytes of a PNG, JPEG, GIF or WebP (the declared type and the magic bytes must agree, `400 unsupported_type` or `400 bad_image` otherwise; SVG is not accepted, the browser rasterises it), strips Exif, XMP, IPTC, comments, text chunks and anything after the end of the image without decoding pixels, refuses a claimed size over 36 megapixels or 16384 px a side (`413 too_many_pixels`), and stores the result under `DATA_DIR/assets/<aa>/<sha256>` with `201` for a new file on the board and `200` for one it already had. `POST …/assets/claim` gives a board a file another readable board owns without moving bytes; `GET` and `HEAD …/assets/:hash` answer only through a board that owns the hash, with `nosniff`, a sandboxing CSP, an `ETag` and a private immutable cache header, and `404` for any other board. Owners and editors upload (open mode: everyone who can reach the board), every role that can open the board reads. Limits: 10 MB per file, 100 MB per board (50 MB in open mode, where anyone with a link can upload), an optional instance cap, 60 uploads and 20 MB per person per minute (`429 rate_limited`), `402 storage_full` over a quota. Set with `TABULA_ASSETS`, `TABULA_ASSET_MAX_BYTES`, `TABULA_ASSET_BOARD_QUOTA` and `TABULA_ASSET_TOTAL_QUOTA`; `/api/me` and `/api/config` report `images: true`. Accounts mode keeps the index in a new directory table (`assets`, schema version 8) and audits `asset.upload` (an Images filter in the audit log); open mode keeps `assets/index.json`. See `docs/images.md`.
- Team chat, slice 1: the server (TAB-132, `docs/chat.md`; no screens yet). Accounts mode only, off unless `TABULA_CHAT=on`; `/api/me` then says `chat: true`. Board chats live in their own database, `DATA_DIR/chat.sqlite` (created on first use, own schema version), never in a board's Yjs room. The server is the only writer: author, time and order come from the session and the row id, never from a request body. REST: `GET` and `POST /api/chat/board/:id/messages` (pages of 50, at most 100, `before` cursor; a retried `clientId` answers `200` with the stored message), `PATCH` and `DELETE /api/chat/messages/:id` (the author edits, any time, marked edited; the author or the board owner deletes, the text is overwritten and only a moderator's delete is audited, as `chat.delete`, ids only), `PUT /api/chat/board/:id/read` (a read marker that only moves forward, open while a hosted workspace is read-only), `GET /api/chat/unread`, and `GET`/`PUT /api/admin/chat` (viewers may post, off by default; keep messages, one year by default, the deleting job follows; audited as `chat.settings`). Commenters and up post, viewers only when an admin allows it, guests only on boards they were given; a channel someone cannot read is a `404`. Text is normalised and checked on the server (NFC, no control or invisible characters, at most two blank lines in a row, 1 to 2000 characters, at most 10 `@{userId}` mentions, a mention of someone who cannot read the chat stored as `@someone`). Posting is limited to 20 a minute per chat, 60 a minute and 5 in two seconds per person, edits and deletes to 20 a minute (`429` with `Retry-After`). A new `/chat` WebSocket (session cookie and Origin like `/sync`) sends JSON frames: `hello` with the unread summary, then `message`, `edit` and `delete` for subscribed chats, counts only (`unread`) for other chats the person can read, `read` to the person's other tabs, `closed` when access is lost, `readonly`; it closes with `4401` when the session ends, allows 10 sockets per person and 50 subscriptions per socket, and drops a socket more than 1 MB behind. Backups copy `chat.sqlite` with `VACUUM INTO` like the directory, and a whole restore brings it back.

- Live AI runs (TAB-141, TAB-123 step 1: the server side; the AI bar and the previews follow). Everyone on a board now hears about its AI runs: the relay sends a new message type (6) with a snapshot when a socket joins while runs are open and a patch for each change, built per socket from the rules in `server/ai/policy.mjs`, so viewers and commenters see runs and nobody is sent the prompt (`PROMPT_VISIBILITY = 'runner'`, until Johan decides). - Swiss design pass: the Select, Hand and Pen icons are re-centred in their 24 px box; every button now has the same 9 px inset on all sides (22 px icons in the 40 px toolbar buttons, 18 px in 36 px buttons, 16 px in labelled buttons); padding is symmetric on the top-right tray, step list, steps popover, quick-action chip, tiles and the sticky colour tray; the close buttons line up with the title inset; drawers and tool trays keep the same gutter when the toolbar narrows on short screens; the running flow-bar step is 36 px high so its end buttons have even spacing.
- The app is now called Mira (it was called Driftboard in the interface and documentation). Saved boards, settings and old .drift files keep working: only user-visible text changed.
- Text, drawings, icons, connectors and frame titles drawn on the canvas now follow the theme's ink colour, and exports (SVG and PNG) always use the light default colours on white.
- The properties panel is hidden until you press More in the quick-action bar, and has a close button. Its Shape list is grouped.
- Locked items are click-through background: clicks and marquee selection pass over them, Select All skips them, and they can't be edited or used as connector targets. Press and hold for 0.6 seconds to unlock one. Dot voting still works on locked notes.
- Locking an item clears the selection.
- Connector anchors and hover dots now sit on a shape's outline instead of its bounding box, so connectors meet triangles, stars, arrows and the like at the visible edge.
- The default size of a new triangle is now square, like the other symmetric shapes.
- Rewrote ternary/short-circuit expression statements in `src/app.ts` as `if` statements and simplified small lint findings in `src/mermaid.ts`, `src/markup.ts` and `test/core.test.ts`, with no change in behaviour.
- In accounts mode the name in Your name and colour is the account name and is saved to the server; the Share dialog explains who can open a board.
- nodemailer upgraded to 10 (fixes high-severity advisories); it ships its own types, so `@types/nodemailer` is removed.

### Fixed
- Person colours now pass contrast (TAB-197). Initials and names are drawn white on a person's colour, which was only 2.95 to 4.38:1 for six of the eight, and the amber, teal and orange outlines (remote selections, cursor arrows, AI run outlines) were 2.6 to 3.0:1 on the light canvases. The eight colours are now darker and every one gives at least 4.5:1 with white text and at least 3:1 on the canvas of every theme; the hues stay the same eight. A colour saved before (your profile, comment pins and avatars, other people's cursors) is shown as its replacement, and any other colour takes the nearest of the eight. `test/person-colors.test.ts` fails if a colour regresses.
- Flaky tests (TAB-180). Relay tests took their ports from fixed random ranges that overlapped between test files, and between suites running on one machine, so a relay could find its port taken and die on start; they now ask the system for a free one (`test/free-port.ts`). Every helper that starts a relay waits `RELAY_START_MS` (30 seconds, `test/relay-timing.ts`) in place of 8 or 15, and `testTimeout` and `hookTimeout` in `vite.config.ts` are 60 seconds. `relay.test.ts` waits for the room file before it stops the relay, in place of a fixed 1.3 second sleep, which a loaded Windows runner outran (Windows cannot save a room on the way out). `icons-build.test.ts` no longer reuses the output directory of a build that just failed, which failed about 1 run in 40 with ENOTEMPTY. The CI tests on Windows run in two shards (`vitest --shard`), one job per shard and node version, the other systems unchanged.
- Bring to front and Send to back with several objects selected gave all of them the same layer key, so their order among themselves fell back to their ids. Each now gets its own key and the selection keeps its relative order (TAB-159).
- The Markdown summary (Menu, and Summary in the session bar) no longer lists other people's private-writing notes before the reveal, and no longer shows the vote totals of the running vote before the reveal (TAB-139). Totals of finished votes are unchanged.
- Side panels clear the top bars at every width (TAB-133): the comments and properties panels used a fixed 72 px and opened over the Share bar at narrow widths. `--panel-top` is now measured from the bars' real height (`src/ui/panel-top.ts`), so comments, history, properties and the poll card start below them even when a bar wraps.
- Relay shutdown on Windows (TAB-131): the relay now also saves its open boards on Ctrl+Break and when its console window is closed (SIGBREAK and SIGHUP), not only on SIGINT and SIGTERM, which Windows never sends. Before, those two ended it without writing the last edits. A second signal while it is shutting down is ignored, and a parent that starts the relay with an IPC channel can send `{ type: 'shutdown' }` for the same graceful stop on every system. The README has an "On Windows" note for nssm and WinSW: stop with Ctrl+C, wait a few seconds before a hard kill, never `taskkill /F` or `Stop-Process`.
- Narrow windows (TAB-112): the quick-action bar now stays below the top bars (it could land on Share and the menu at about 500 px) and above the properties panel when a phone docks that panel to the bottom edge. While a drawer is open at phone width, the quick-action bar and the properties panel wait, where they were, until it closes, so they no longer pile up on the Stickers drawer. The version history panel starts below the top bars through the shared `--panel-top` instead of a fixed 72 px, so it no longer covers Share and the menu. A second sticker or icon added by click no longer lands exactly on the first: each one steps 24 px right and down from the last, as Duplicate does, and starts over at the view centre after the view moves, the last one is moved or deleted, or the run would leave the view. Dragging onto the board is unchanged.
- Clicking a connection dot no longer drops the new connected copy on top of other shapes: the copy goes in the nearest free spot in that direction, with a little room around it.
- The admin audit log reads the trial-ending mail row (`cloud.notify`) as "System sent the trial-ending notice to 2 workspace owners" instead of showing the raw action name.
- A commenter's board now shows a Can comment badge, as the home list does, instead of View only. The admin dashboard shows its Access tokens section only when AI tool access is turned on. `docs/polls.md` no longer says polls are unbuilt.
- The Keyboard shortcuts dialog now lists every shortcut and is built from the same table as the key handler; it described [ and ] the wrong way round.
- The Delete button in comment threads used the plain theme red on the dark comment panel, which was hard to read; it now uses the lighter tray red like other error text on toolbars and dialogs, and a test checks red text on trays reaches 4.5:1 in every theme.
- Armed confirm buttons in the admin dashboard (red outline, red fill on hover) now reach 4.5:1 contrast at rest and hovered in every theme, following the theme red adjustments; the hovered pair is now checked in tests.
- Connection dots stay visible while the pointer crosses a connector that already leaves that side, so a shape side can take a second connector. Clicking a connection dot connects to the shape already next to it on that side, if there is one, instead of always making a new shape. The quick-action bar moves below the selection when above it would cover one of its connectors.
- A deleted board that a workspace admin opens (from Admin > Boards) is read-only, with a Deleted board badge, until it is restored. Before, it opened as an ordinary editable board whose changes were kept.
- Admin Overview: the members tile now counts everyone, so its role breakdown adds up (it showed active members over a breakdown that included disabled ones), and the disabled tile shows how many are active. Members, teams and boards all count everything, with the disabled, archived or deleted part underneath.
- Boards created with a title through `POST /api/boards` no longer open as "Untitled board" while the board list shows their name, and renaming a board through `PATCH /api/boards/:id` now renames the board itself instead of being undone at its next save.
- Polls: revealing the results and moving the session on at the same time on two devices no longer loses one of the two. A poll's revealed, opened and closed fields now each have their own key (`pollState`), and existing polls move over when a board opens.
- The Icons and Stickers drawers no longer say "needs a connection" while you are online. A failed search says whether you are offline, the icon service is busy or not responding, or icons could not be loaded, and has a Retry button. The drawer retries by itself when the browser comes back online, or once after a rate limit or an unresponsive service (10 seconds, or the Retry-After wait up to 60 seconds).
- Icon and sticker results stay inside their drawer: the grid is contained and shows a loading line while a search runs, and a superseded or closed request is aborted, so a late response never reaches the drawer.
- Secondary grey text on panels in Ayu, and red error and delete text in Default, Kanagawa and Evergreen, were below WCAG AA contrast; the theme colours are adjusted slightly (same hue) so every text colour now reaches 4.5:1 on both the page and panel backgrounds, checked in tests.
- Typing a connector label happens in the same small paper pill the label is drawn in, sized to the text, instead of a large white box with a blue border; the caret takes the label's colour.
- Editing a UML class or a connector label keeps the object's own colours: the class editor uses its fill and text colour, a label its connector's colour, instead of always a white box with dark text.
- Admin dashboard polish: names, emails and board titles that are cut off show in full as a tooltip; Sessions shows the browser and system each session signed in from (recorded from now on) and the time of sign-in; the audit log has a Sessions filter for revoked sessions; on desktop, cells no longer repeat their column heading ("Signed in", "Edited").
- Admin dashboard: arming or toggling a row action (Remove, Disable/Enable, Archive, Delete, Revoke) no longer moves the buttons; an armed button reads "Click again" and names the action for screen readers and in its tooltip. Focus stays on the same control after a change, or moves to the next row's when a row is removed. Outcomes show in the top bar instead of a toast that covered rows, and clear when you switch tabs.
- Buttons and text that were hard to read on the dark themes (Ayu, Kanagawa, Matrix): the home screen's New board button (yellow on a pale background), hover colours, error and sync-status text, select arrows and the home dot grid now follow the theme. A test fails on any new hard-coded colour in the CSS, and the theme contrast test now also covers text on paper and paper on ink.
- Icons whose SVG bodies use element ids, such as emoji gradients, no longer draw each other's gradients: ids are scoped per object at render and export time.
- A directory database refused for a newer schema is now closed instead of left open, so its file can be removed (on Windows it stayed locked).
- On the home screen, boards that someone shared with you no longer appear under Personal, and the sign-in card is centred on the page.
- The highlighted option in segmented controls and colour swatches now follows your click. In Board settings the Grid control stayed on Dots after choosing Lines, Isometric or None; the same stale highlight affected the quick-action popovers.
- Labels in the board menu were right-aligned next to their icons; they are now left-aligned.
- A locked item that overlaps an unlocked one can now be unlocked with a long press; double-clicking a locked item no longer creates a stray text box; arrow-key nudging a frame no longer moves its locked children; an item locked by a collaborator is dropped from your selection.
- Text boxes in shapes and sticky notes no longer collapse to a negative size when resized very small, and quick-action popovers close when you zoom or pan instead of floating in place.
- Quick-action popovers open away from the selected item instead of over it.

- Text in shapes and sticky notes no longer sits at the top while you type and jumps to the centre when you finish. The editor now uses the same box, auto-shrink and layout as the renderer. Use-case, state, lifeline and component elements still use the old editor centring.
- Polls on a phone: after Finish, the Poll results block wraps so Add results to board and Clear poll stay reachable; the session bar clears the left rail; the answering card sits below the top bar and its header stays in view while the options scroll, with no shift when the first answer arrives; the composer's option list scrolls so Start poll and Cancel stay on screen; and the Stickers and Icons drawers open below the Share and menu bar.

The question field is focused right away when the composer opens, rather than on the next animation frame, which a background tab never runs.
