# Changelog

All notable changes to Tabula are documented here, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Live AI runs (TAB-141, TAB-123 step 1: the server side; the AI bar and the previews follow). Everyone on a board now hears about its AI runs: the relay sends a new message type (6) with a snapshot when a socket joins while runs are open and a patch for each change, built per socket from the rules in `server/ai/policy.mjs`, so viewers and commenters see runs and nobody is sent the prompt (`PROMPT_VISIBILITY = 'runner'`, until Johan decides). Runs live in memory (`server/ai/live.mjs`): a ready run expires after 10 minutes, a board holds at most 12, and a board that unloads drops its runs. `POST /api/ai/runs/:id/resolve` with `{ action: 'accept' | 'discard' }` settles a ready run, first come: an accept hands the proposal to the person who clicked, whose app writes it as one undo step, and anyone after gets `409 ai_run_resolved`; by default any board editor may settle. Audited as `ai.run.accept` and `ai.run.discard`. The run stream's first `progress` event and its `result` now carry the `runId`. Open mode has the same route and messages, with no name for the runner. See `docs/ai.md`, "Live runs".
- `npm run test:repeat -- [files] [--times 20] [--platform win32] [--bail]` (TAB-154), a flake gate: it runs test files N times under `CI=true`, so the CI settings of `vite.config.ts` apply, prints a line per run and a summary of which tests failed in which runs (read from vitest's JSON reporter), and exits 1 if any run failed. Without files it takes the test files changed versus `origin/main`, committed or not. `--platform win32` sets `TABULA_TEST_PLATFORM=win32`, which `test/platform.ts` turns into `isWindows` for the tests that branch on the platform (`backup-api`, `relay-shutdown`).
- AI features, bring your own key (TAB-97, slice B: running the features; the board buttons and the proposal preview follow). `POST /api/ai/run` takes `{ feature, boardId, input }` for `generate` (a prompt and an optional count of 1 to 30), `summarise` (a summary or a retro, with action items, of the board, a frame or a selection) or `cluster` (2 to 200 selected stickies into 2 to 12 titled groups) and answers as server-sent events: `progress`, then one `result` with the proposal (`create` stickies and an optional frame, or `group`), a `cut` flag and a token summary, or one `error`. Everything before the stream (signed in, AI on for the workspace and the feature, guests when AI is members only, the right to edit the board, a read-only hosted workspace, a key that resolves and opens, the rate limits) is a plain HTTP status in that order. The board is read with the MCP reader: private notes are withheld, no comment or author name is sent, at most 400 objects and 60,000 characters go nearest the selection first, and the text is fenced and cleaned as the MCP tools do, with the person's prompt outside the fence. The model's answer is untrusted plain text: invisible and control characters are removed, unknown keys, unknown or non-sticky or private ids, ids twice or missing, too many groups, colours outside the palette and over-long text refuse the whole answer (`ai_invalid_proposal`), never part of it. One run at a time per person, up to three at once on a shared key (workspace or operator) and one on a personal key, 20 runs per person and 200 per workspace an hour by default (the admin's limits, kept in memory and reset by a restart), key saves limited to 10 an hour and one check at a time, a 120 second timeout and an abort when the client closes the request; a refusal from the provider is an `ai_refused` event. Each run writes one audit row (`ai.generate`, `ai.summarise`, `ai.cluster`) with board id, model, key source, counts and tokens and no text, shown as sentences in the audit log. Open mode has the route too: only with `TABULA_AI_API_KEY` and `TABULA_AI_OPEN=1`, counted per client address plus one instance-wide count, audited as a log line. `api.mjs` lets a route stream; `board-ops.mjs` exports the reader it already used. See `docs/ai.md`.
- AI features, bring your own key (TAB-97, slice A: settings and keys; the features themselves follow). Anthropic is the only provider (`@anthropic-ai/sdk` 0.128.0, exact pin; Claude Opus 5.5 by default, Claude Sonnet 5.5 and Claude Haiku 5.5 selectable). In accounts mode an owner or admin turns AI on under the new AI tab of the admin dashboard (features, model, personal keys, members only, hourly limits, the workspace key) and, when allowed, each person adds their own key under Your AI key in the board menu. Keys are verified with the provider before they are stored, encrypted at rest with AES-256-GCM under `TABULA_AI_SECRET` (a random nonce per row, bound to the scope and the person), shown afterwards only as their last four characters, never logged and not returned by any endpoint; `TABULA_AI_SECRET_PREVIOUS` rotates the secret. Without a secret the server refuses to save a key (`ai_unconfigured`), and it refuses to start with a malformed one. New migration (`ai_keys`), `GET /api/ai/config`, `PUT` and `DELETE /api/ai/keys/me`, `GET` and `PUT /api/admin/ai`, `DELETE /api/admin/ai/key`, audit rows `ai.settings`, `ai.key.set` and `ai.key.delete` with an AI filter in the audit log. Open mode has AI off unless both `TABULA_AI_API_KEY` and `TABULA_AI_OPEN=1` are set (anyone with a board link then spends that key); `TABULA_AI_PROVIDER` and `TABULA_AI_MODEL` are also read. Error logs now write an AI or provider error as its code and status only. See `docs/ai.md`.
- Connectors that share a side of a shape now spread along it, ordered by where they go, instead of overlapping at the middle (TAB-81). The ends sit evenly either side of the middle, at most 28 units apart, on the outline of the shape (rectangles, ellipses, diamonds and the other polygon kinds, terminators and cylinders); a lone connector stays at the middle. Heart, cloud, round speech bubble, document, delay and display shapes keep every connector at the middle. Exports and template thumbnails draw the same.
- One shared tooltip for icon buttons and other tipped controls, in place of the browser's native `title` pop-ups: it opens after half a second of mouse hover (never on touch or pen) or at once on keyboard focus, and shows the label and, where there is one, the shortcut as a key chip read from the shortcuts table. It sits above the control, below when there is no room, shifted to stay inside the window and never over the control. After one has shown, the next control opens at once for a moment. It closes on leaving, blur, Escape, a click, a scroll or a resize, is a single `role="tooltip"` element named by `aria-describedby` while open, follows the theme, and does not fade under reduced motion. Disabled buttons that explain themselves (admin and version history) keep the native title. A long press on an icon no longer opens the system menu on touch.
- Share dialog roles (accounts mode): the board owner and workspace admins give a person or a team Editor, Commenter or Viewer access from the Share dialog, change it, and remove it. Changes reach open boards at once.
- AI tool access link in the top bar of the Boards and Templates pages, shown only when AI tool access is turned on for the server; it opens the same dialog as the board menu.
- Off-site backups (TAB-89, `TABULA_BACKUP_*`, off unless the endpoint, bucket, access key, secret key and encryption key are all set): the relay copies `DATA_DIR` to an S3-compatible bucket on a schedule (hourly by default, first run one to five minutes after start). The database is copied with `VACUUM INTO` while the server runs, an open room is taken from memory and any other room from its file, and a board's history is read index first. Everything is encrypted on the instance with AES-256-GCM under keys derived from `TABULA_BACKUP_KEY` before it is uploaded, named by a keyed hash so the provider learns nothing, and listed in a manifest that is written last, read back and verified; a changed file is uploaded once. Retention is configurable (`TABULA_BACKUP_KEEP_HOURLY_HOURS`, `TABULA_BACKUP_KEEP_DAILY_DAYS`: 48 hours of hourly and 30 days of daily by default), old manifests are pruned and unreferenced objects removed after an hour, and never on partial knowledge. A small SigV4 client over `fetch` (no SDK) retries 5xx, 429 and network errors and never a 403. `TABULA_BACKUP_KEY_PREVIOUS` reads backups made before a key change. `GET /api/internal/backup-status` reports the state to the control plane (`{enabled: false}` when off), the log, status and audit rows (`backup.run`, `backup.failed`) never hold a key, secret or signature, and a failing backup never affects the relay. Restore and an admin screen follow. **Losing the key means the backups cannot be read.** See `docs/backups.md`.
- Backups (TAB-126): a run that found nothing to do is no longer written to the audit log (only runs that uploaded, repaired or deleted something are; the status still records every run), a stopping relay waits up to two seconds for a backup run in progress before closing the database, and `docs/backups.md` gives measured copy times for the directory database.
- User guide at `/docs/`: static pages built from `docs/guide/*.md` together with the app, readable without signing in, themed like the app and searchable in the browser (`/` focuses the search). Linked as Help in the top bar and as User guide in the board menu (new tab). The relay serves it from `dist/docs` only and answers unknown guide pages with a 404 guide page; the service worker leaves it alone.
- Custom templates (open mode): select objects or use the whole board and choose Save as template (quick-action bar or board menu) with a name, category and description. Saved templates appear under My templates on the Templates page, first in the Boards page strip, and in the board's Templates drawer; use one as a new board or insert it into the current board in one undo step. Stored in this browser and kept in sync across tabs. Every template card now shows a thumbnail drawn from its contents, in the current theme.
- Edit a saved template on a scratch board (My templates card menu, Edit; `#/t/:id/edit`): an in-memory board that never syncs and is not listed under Boards, with a banner to change its name, category, description and session steps, then Save template or Cancel (asks before discarding changes). The same menu renames and duplicates a template and exports it as a `.tabula-template.json` file; Import template on the Templates page adds one from a file. Built-in templates stay read-only but offer Duplicate to edit, which makes a personal copy in the same category.
- Custom templates in accounts mode (TAB-82 step 5): templates are saved on the server instead of in the browser and can be shared with just you (the default), a team you belong to, or the whole workspace (workspace owners and admins only). The Save dialog has Share with; the Templates page splits My templates from Shared with me with a small label on each card; Edit, Rename and Delete show only where you may change the template, and Duplicate makes a personal copy for anyone who can see one, except guests. Guests can use the templates of their teams but not save or duplicate any. Categories are a fixed list on the server too. After signing in, a one-time offer uploads the templates saved in this browser as personal templates (once per browser, nothing is sent without the click). The list and the templates used are cached for offline use (tagged with the server, cleared on sign-out) and saving is off while offline. New routes `GET/POST /api/templates`, `GET/PATCH/DELETE /api/templates/:id` and `POST /api/templates/:id/duplicate` (soft delete, `404` for what you cannot see, `403` for what you cannot change, `402` while a hosted workspace is read-only, `413` over 1 MB with a per-route body limit, at most 200 templates per person), audited as `template.create`, `template.update` and `template.delete` and shown in the admin audit log. The server rebuilds every template from the fields it accepts and refuses unsafe SVG in icons and stickers (scripts, `foreignObject`, event handlers, external or `data:` links, `<style>`, entities). MCP tools can list templates (`list_templates`, read token) and add one to a board (`use_template`, write token and editor role; objects only, no session steps or fonts) but cannot create, change or delete them. Directory schema version is now 6. See `docs/custom-templates.md` and `docs/mcp.md`.
- Comment authorship enforced on the server (accounts mode): the relay checks every comment write against the author's role and undoes what the rules forbid, so moderators (board owners, workspace admins and team admins) may delete others' comments but not edit them, authors and names are stamped from the account, imported and pre-accounts comments are marked, and the person whose change was undone gets a short notice. Resolving is for the author and board editors. See `docs/comment-authz.md`.
- Desktop app, phase 1 (`desktop/`, `docs/desktop.md`): `.drift` files opened from the system import as new boards, relay `auto` means off, there is no service worker, and exports open a native Save dialog. The app keeps a `.drift` copy of every board in its data folder (written after changes, restored at start for boards the webview's storage lost, merged into a board that opens empty, removed when a board is deleted), because WebKit can clear a custom-scheme origin's storage: tested on macOS with a doctored tracking-prevention database, where it deleted IndexedDB after 30 operating days without interaction. `identifier` and `useHttpsScheme` are locked by a test. Tested on macOS only; Windows and Linux were not run. Browsers are unaffected.
- Self-hosted icon sets (TAB-101): the Icons and Stickers drawers no longer call the Iconify API, whose 429 rate limit broke them. `npm run build` now also builds every icon set whose licence allows it (188 sets, 344,033 icons, from the pinned `@iconify/json`) into `dist/icons/`: a manifest, a search index and 96-icon shards per set, gzipped and content-hashed, plus `LICENSES.txt`. The relay serves them with a long cache lifetime and a real 404; the service worker keeps what was fetched in its own cache, which survives app updates. Search runs in the browser over names, aliases and categories; previews are built from the shards. "Download for offline" stores a set (or the popular sets, or the three sticker sets) on the device, with progress, cancel, update and remove. The Iconify API stays only as an online fallback: an "Online sets" button loads the other sets Iconify lists whose licence is allowed, and only those are searched through Iconify. Sets under NonCommercial, ShareAlike, copyleft and unclear licences, hidden sets and every set Iconify files as unmaintained (Font Awesome 4 to 6 among them) are not hosted. An Icon credits dialog (Icons and Stickers notes, home footer) lists every set by what its licence asks for, with a trademark note for logo sets. `ICON_SETS=curated` builds 19 sets instead (about 86 MB image instead of 141 MB), also as `docker build --build-arg ICON_SETS=curated`. Rebuilds with unchanged inputs are cached in `node_modules/.cache/tabula-icons`. The service worker cache is `tabula-v2`. The desktop bundle leaves the icon sets out (its build runs `build:app`; see `docs/desktop.md`). Tests: the build, the search, the client, the relay's `/icons/` route and the offline store. See `docs/icons-selfhost.md`.
- Templates page (`#/templates`): every template on a solid card, with category filters and search. The home screen links to it from a short Start from a template row.
- Desktop app spike (`desktop/`, `docs/desktop.md`): a Tauri 2 shell around the built web app, with a `.drift` file association and the Rust side of opening a file. `npm run desktop:dev` and `npm run desktop:build` need Rust and are not part of CI or any release. The page records what was verified on macOS, how storage, relays, updates and signing would work, and a phased plan. Nothing in the web app or the relay changes.
- Tests for live role changes and session expiry on open sockets, and for running behind a reverse proxy; a "Behind a reverse proxy" section in the README.
- Smart guides while moving and resizing objects. Edges and centres snap to nearby objects with a guide line drawn between the aligned objects (not across the whole view), and equal spacing is shown and snapped to: the gap to the nearest neighbour matches an existing gap in the same row or column, or the object lands exactly midway between two neighbours, with a bracket and the distance on every equal gap. Resizing snaps only the edges being dragged. Alignment and spacing beat grid snapping when within 6 screen pixels; hold Alt to bypass guides and the grid. The guides use a new `--guide` theme colour, checked for contrast in all five themes. Hidden private notes no longer show up as guide targets. See `docs/guides.md`.
- Polls: a facilitated question with 2–10 options, run as a session step (new `poll` step mode) or started from a quick poll button on the toolbar. One answer per person, changeable until the poll closes; results stay hidden until reveal, and ranked results copy as Markdown or go on the board as a sticky. Answers live in the board document, so they work offline, sync, and travel in `.drift` and JSON exports; the Markdown summary includes revealed polls. See `docs/polls.md`.
- Stickers: a Stickers drawer (Fluent, Twemoji and Noto emoji from Iconify) places colour emoji on the board. They work offline and export with the board, and have no colour control. A React button in the quick-action bar drops a reaction next to the selection. See `docs/stickers.md`.
- Version history: browse earlier versions of a board, preview one read-only and restore it (board menu, Version history). The relay keeps full-state snapshots next to the room files (`<DATA_DIR>/history/<boardId>/`): automatically while people edit (at most every 10 minutes, when everyone has left, and the board as it was just before a large deletion), and on demand as named versions. Automatic versions are thinned (all for a day, hourly for a week, daily for a month; 64 MB per board). A restore is an ordinary edit: it syncs to everyone, undoes with Ctrl+Z in one step, saves the board as it was first as a version, and shows up as a new version. Owners and editors only; works in open mode too. Restoring leaves the board title, the running session, votes and comments alone, and is refused while a session runs. See `docs/history.md`.
- Audit rows in accounts mode for saving, renaming, deleting and restoring versions (`board.version.*`), with readable sentences in the admin dashboard.
- AI tool access over MCP (`TABULA_MCP=on`, off by default): AI tools such as Claude Code read and edit boards through `POST /mcp` (stateless JSON-RPC over HTTP, no new runtime dependency). In accounts mode each person makes personal access tokens under AI tool access in the board menu (read, comment or edit level, optional board list, 7 to 365 days, revocable, hashed at rest, listed in the new Access tokens tab of the admin dashboard, audited as `mcp.*`); a token acts as its owner and never as more, the role is checked on every call, and workspace owners and admins must name the boards of tokens that can comment or edit. In open mode one shared token (`TABULA_MCP_TOKEN`, scope `TABULA_MCP_SCOPE`, read by default) is accepted instead. Edits go through the relay's live room documents, so people on the board see them at once. Tools: whoami, list_boards, get_board, get_objects, create_objects, update_objects, delete_objects, list_comments, add_comment and reply_to_comment. Board text reaches the model fenced, escaped and stripped of invisible characters, private notes of a running session are withheld, and a read-only hosted workspace refuses writes. See `docs/mcp.md`.
- Hosted workspaces (`MIRA_CLOUD_TOKEN`, `MIRA_CLOUD_URL`, `MIRA_CLOUD_WORKSPACE_ID`, accounts mode only; off and invisible when unset): a control plane can read seat counts (`GET /api/internal/usage`) and set a seat limit, a read-only switch and a banner (`PUT /api/internal/limits`, bearer token, stored in the new `settings` table). A read-only workspace drops board and comment updates on open and new sockets and answers writes with `402 read_only`; a full workspace refuses new invites, invite sign-ins and seat-taking role changes with `409 seat_limit`; `/api/me` reports the workspace. The instance opens the billing portal for the owner (`POST /api/billing/portal`) and reports seat counts to the control plane. The app shows the banner on the home screen and boards, a Workspace is read-only badge, and an owner-only Manage billing button in the admin Overview, and refreshes `/api/me` every five minutes. See `docs/cloud.md`.
- Hosted workspaces: a read-only change reaches open boards at once. The relay sends a small hint (message type 4, `{readOnly}`) on every open sync socket when the switch flips; the app asks `/api/me` straight away (one request for both sockets) instead of waiting up to five minutes, and reconnects the board when the workspace is writable again, so edits typed during the lock reach the server without a reload. The five minute refresh stays as the fallback. See `docs/cloud.md`.
- Hosted workspaces (TAB-113): `POST /api/internal/notify` lets the control plane have the instance mail the workspace owners that the trial is ending (`{template: 'trial-ending', date}`, bearer token, cloud mode only). Only enabled owners are mailed, through the instance's own mailer; `200 {sent}`, `502` when every mail failed so the control plane retries, and a repeat of the same date answers `{sent: 0, duplicate: true}` without mailing again. Audited as `cloud.notify`, without addresses. See `docs/cloud.md`.
- `npm run dev:accounts` runs the dev server in accounts mode (sign-in links printed to the console).
- `MIRA_MAIL_WEBHOOK_TOKEN`: sent as a bearer token with each mail webhook request, so a hosted mail relay can authenticate the instance.
- Admin API for workspace owners and admins (`/api/admin/*`): instance overview, members with last seen and session counts, sign people out (all sessions or one), boards including deleted ones with restore, sessions list and a paged, filterable audit log. See `docs/admin.md`.
- Admin dashboard (`#/admin`, owners and admins): overview, members (role, disable, sign out everywhere, remove), teams, boards (delete, restore), sessions and a readable audit log. Linked from the home screen and the board menu.
- Email through your own SMTP server (`MIRA_MAIL=smtp`, `MIRA_SMTP_URL`, `MIRA_MAIL_FROM`) for sign-in links; webhook and outbox payloads now also carry the kind of email (`template`, `params`). The relay reads a `.env` file at startup, and `.env` files are gitignored.
- Comments: threaded comments pinned to a place or an object (C key or the speech-bubble tool), with reply, edit, delete, resolve/reopen, a Comments panel, a show/hide toggle in the board menu and a count badge. Pins follow their object through move, resize and rotate, are hidden for notes that private writing hides, and are left out of image exports. See `docs/comments.md`.
- Commenter role for shared boards (accounts mode): can read and comment but not edit; viewers can read comments.
- Comments data layer: each board has a sibling comments document (synced in its own room, persisted offline, included in .drift and JSON exports); the UI follows.
- Board role `commenter`: can read the board and write its comments, but not edit it (server side; the comments feature itself follows).
- Accounts and teams mode (opt-in with `MIRA_AUTH=on`): email sign-in links, workspace and team roles, per-board sharing, a server-side HTTP API for all of it, and a relay that checks access on every connection and makes viewers read-only. Open mode is unchanged. See `docs/accounts.md`.

### Changed
- Nobody can make you look somewhere, or follow them. "Bring everyone to my view" is now "Ask everyone to look here": it sends a request that appears as a small card with Go to, Follow, Dismiss and Mute, and it moves nobody. Moving the session to a step flies only the person who changed it; everyone else gets a card saying who moved to which step. Cards go away after 20 seconds. Follow tracks that person's view until you pan, zoom, press Esc or they leave. Mute (remembered per person and board in this browser; undo it from Muted people in the board menu) silences someone's requests. Anyone, including people with view-only access, can ask; a person can ask once every 10 seconds, and repeats within 10 seconds are ignored. Requests travel on presence, not in the board, so old browser tabs that still write a shared view move nobody. See `docs/focus-requests.md`.
- The home screen is now a Boards page in the Swiss style: a shared top bar (Boards, Templates, Admin, your name, Sign out), one New board action, a search field, and each team's boards as a table with name, last edit and access (a badge only for View only and Can comment boards). The marketing text and the dot grid behind the page are gone, which also fixes the template list being hard to read on dark themes.
- Sign-in, check-your-email and invite screens use the Swiss style of the admin dashboard: the Tabula wordmark over a ruled top bar, a flush-left form column instead of a rounded card, square fields and buttons, and notices and errors marked with a coloured left rule.
- Dialogs, menus, popovers and toasts follow the Swiss style: square corners, a rule under each dialog title, small uppercase labels, outlined square buttons and fields, and a yellow bar instead of a fill for the selected menu item. Dialogs drop the soft shadow; menus and popovers keep a faint one over the board.
- Properties panel: font size and opacity step with the mouse wheel or a trackpad over the field, the arrow keys (Shift for ten at a time) or by typing, and each burst is one undo step. Font, weight, shape, class kind, arrowheads and UML relationship use a new list that previews an option on the selection while you point at it or arrow to it; leaving the list or Escape puts it back, a click or Enter keeps it (one undo step). On touch, a tap picks at once.
- Admin dashboard redesigned in a Swiss style: numbered section index, large flush-left headings, overview figures in a ruled band, tables on hairlines instead of rounded cards, square buttons, chips and badges, and no shadows. Manage billing is now the primary action.
- The app is now called Tabula (it was called Mira). Saved boards, settings and old .drift files keep working: only user-visible text changed. Server settings are now `TABULA_*` (`TABULA_AUTH`, `TABULA_BASE_URL`, `TABULA_OWNER_EMAIL`, `TABULA_CLOUD_TOKEN` and so on); the old `MIRA_*` names are still read, with a deprecation warning at startup, and the `TABULA_` name wins when both are set. The session cookie is now `tabula_session` (`__Host-tabula_session` over https), so everyone signs in once more after the upgrade. The browser app sends the CSRF header `x-tabula: 1`; the server still accepts the old `x-mira: 1` as well (deprecated). The service worker cache is renamed, and the old one is deleted on first load. Docker commands in the README use `tabula`.
- The `.drift` hint in the board menu now reads "Board with its sync data" instead of "Full history": the file holds the board's sync state, but content deleted earlier is not in it.
- The relay now saves a room at least every 30 seconds while it is edited without a pause (it used to wait for a second of quiet, which could postpone saving indefinitely).
- Minimum Node version is now 22.13 (built-in SQLite for the upcoming accounts mode).
- Swiss design pass: the Select, Hand and Pen icons are re-centred in their 24 px box; every button now has the same 9 px inset on all sides (22 px icons in the 40 px toolbar buttons, 18 px in 36 px buttons, 16 px in labelled buttons); padding is symmetric on the top-right tray, step list, steps popover, quick-action chip, tiles and the sticky colour tray; the close buttons line up with the title inset; drawers and tool trays keep the same gutter when the toolbar narrows on short screens; the running flow-bar step is 36 px high so its end buttons have even spacing.
- The app is now called Mira (it was called Driftboard in the interface and documentation). Saved boards, settings and old .drift files keep working: only user-visible text changed.
- Text, drawings, icons, connectors and frame titles drawn on the canvas now follow the theme's ink colour, and exports (SVG and PNG) always use the light default colours on white.
- The properties panel is hidden until you press More in the quick-action bar, and has a close button. Its Shape list is grouped.
- Locked items are click-through background: clicks and marquee selection pass over them, Select All skips them, and they can't be edited or used as connector targets. Press and hold for 0.6 seconds to unlock one. Dot voting still works on locked notes.
