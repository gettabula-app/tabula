section: Added

- AI: an OpenAI-compatible provider (TAB-222, `docs/ai.md`, "OpenAI-compatible providers"), so a key from NVIDIA's catalogue, OpenAI, OpenRouter or a local model server can run the AI bar's features. Both key screens ("Your AI key" and the admin AI tab) have a provider choice, and for OpenAI-compatible a **Base URL** and a **Model**. Test key works for both providers: it checks the key on `/models` and then asks the configured model for one token, because a catalogue can list models that do not answer. The answer must be valid JSON that passes the same checks as Anthropic's; a model that cannot produce it gives a clear error ("Try a stronger instruction-following model") and changes nothing. In open mode the operator sets `TABULA_AI_PROVIDER=openai-compatible`, `TABULA_AI_BASE_URL` and `TABULA_AI_MODEL`.
- An address typed on a key screen is treated as hostile: `https` only, public addresses only (the connection goes to the address that was checked, so a DNS change after the check does nothing), no redirects, a size and time limit, and the key goes only to that address. Audit rows carry the provider, the host and the model, never the key. A key row has a new nullable `model` column (a migration).
- `npm run check:ai-review -- --provider openai-compatible` runs the whole browser check against a fake OpenAI-style server (`scripts/lib/openai-stub.mjs`).
